# Orbio — Registro da sessão (31/08/2026)

Resumo de tudo que foi analisado e implementado nesta sessão: diagnóstico do projeto, checklist de profissionalização e a implementação da landing page pública + infraestrutura de lançamento.

---

## 1. Diagnóstico inicial do projeto

**Stack:** React 19 + Vite + Tailwind v4, Zustand, React Router v7, Supabase (auth) — front-end SPA estático, sem backend próprio.

**Principais achados:**
- O CRM inteiro (leads, deals, pipeline, contatos, empresas, faturas, campanhas) roda em `localStorage` via Zustand `persist` ([src/store/useCrm.ts](src/store/useCrm.ts)) — **não há persistência real nem multi-usuário** para os dados de negócio. Duas pessoas da mesma empresa não veem os mesmos dados.
- Supabase só era usado para login/registro ([src/store/useAuth.ts](src/store/useAuth.ts)) e listagem de usuários ([src/lib/directory.ts](src/lib/directory.ts)).
- O projeto Supabase de produção (`orbio`, ref `qxfvxmxmrhdadgwkwjcu`) estava **pausado** (inatividade do plano free) e sem migrations versionadas no git.
- Ponto positivo: o "Vault" (cofre de senhas) usa criptografia client-side real — PBKDF2 (310k iterações) + AES-GCM, chave não-extraível em IndexedDB ([src/lib/vaultCrypto.ts](src/lib/vaultCrypto.ts), [src/lib/vaultDb.ts](src/lib/vaultDb.ts)).
- `.env` corretamente fora do git; chave do Supabase usada é a pública (anon), como deveria ser.
- Sem RLS auditável (sem migrations no repo), sem rate limiting, sem 2FA, sem auditoria.

**Conclusão:** o produto está visualmente pronto para vender, mas a arquitetura de dados (CRM em localStorage) ainda não suporta uso real multi-empresa — migração para tabelas Supabase com RLS por workspace é o próximo passo estrutural (não feito nesta sessão, ficou registrado como pendência).

**Sobre "cara de IA":** identificado que o domínio `.vercel.app` padrão, e-mails transacionais do Supabase sem marca própria, e um artefato de template (`public/_redirects`, convenção Netlify usada num projeto hospedado no Vercel) eram os principais sinais — o `_redirects` foi removido nesta sessão.

### 3.3 Formulário de contato real (Supabase)

- Tabela nova `public.contact_leads` (id, name, email, message, created_at), RLS habilitada, política de **insert público / sem select público** (ninguém de fora lê os leads de outra pessoa).

- **Nota operacional:** o projeto Supabase `orbio` precisou ser reativado (estava pausado) e a organização estava no limite de 2 projetos ativos do plano free — o projeto `eco-sim-agendamento` foi pausado pelo usuário para abrir espaço. Vale lembrar de reativá-lo quando for usá-lo de novo.

### 3.4 SEO técnico

- [public/robots.txt](public/robots.txt) — permite indexação do site público, bloqueia `/app` (área logada).
- [public/sitemap.xml](public/sitemap.xml)
- [public/og-image.svg](public/og-image.svg) — placeholder de imagem de compartilhamento social.

### 3.5 Política de privacidade e Google Analytics

- [src/pages/site/PrivacyPolicyPage.tsx](src/pages/site/PrivacyPolicyPage.tsx) — rascunho orientado à LGPD (dados coletados, finalidade, retenção, direitos do titular). Marcado explicitamente como rascunho, recomenda revisão jurídica.
- [src/lib/analytics.ts](src/lib/analytics.ts) + [src/hooks/useCookieConsent.ts](src/hooks/useCookieConsent.ts) + `CookieConsentBanner.tsx` — GA4 só carrega se `VITE_GA_MEASUREMENT_ID` estiver configurado **e** o usuário aceitar o banner de cookies. Escopo: só no site público, não dentro do CRM logado.

### 3.6 Limpeza

- Removido `public/_redirects` (artefato de template Netlify, sem função no Vercel).
